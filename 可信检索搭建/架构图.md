# 元层次 Skill 架构图

```mermaid
flowchart TD
    Q([用户提问：某领域的数据])
    
    Q --> STEP0{第零步：<br/>有预置 Skill 吗？}
    STEP0 -->|有| EXIT([转交预置 Skill])
    STEP0 -->|无| P1
    
    subgraph PHASE1["阶段一：领域分析（白名单生成器）"]
        direction TB
        P1[第一步：判断信源结构<br/>树状 / 网状 / 单源垄断]
        P1 --> P2[第二步：发现候选信源<br/>途径1 记忆 + 途径2 搜引用]
        P2 --> P2B[第二步附：实地验证<br/>低成本预筛选·身份+溯源<br/>禁：产生新候选 / 深评]
        P2B --> P3[第三步：两阶段评估]
        
        subgraph EVAL["第三步展开"]
            direction TB
            E1[3.1 第一遍·低成本过滤<br/>查身份 + 数据溯源 → 淘汰不合格]
            E1 --> E2[3.2 排序<br/>.gov优先 + 被引频次]
            E2 --> E3[3.3 第二遍·达标即停<br/>逐个深评→下限封槽<br/>方法/时效/机构]
        end
        
        P3 --> EVAL
        EVAL --> P4[第四步：构建白名单]
        P4 --> P5[第五步：显式记录<br/>槽位终态 / 储备清单 / 淘汰原因]
        P5 --> P6[第六步：落盘<br/>领域档案·可复用]
    end
    
    PHASE1 --> PHASE2
    
    subgraph PHASE2["阶段二：标准检索（六模块）"]
        direction TB
        S1[搜索规划<br/>拆查询 / 匹配信源 / 定关键词]
        S1 --> S2[信源约束<br/>只搜白名单内]
        S2 --> S3[接地规则<br/>只输出检索到的 / 溯源URL]
        S3 --> S4[补搜机制<br/>≤2轮 / 储备补位必先深评]
        S4 --> S5[自检反思<br/>完整·可追溯·时效·一致·边界]
        
        S5 -->|发现缺口| S4
        S5 -->|通过| S6[可审计交付<br/>核心数据 + 交叉验证 + 边界说明]
    end
    
    S6 --> Z([交付 + 领域档案])
    
    style P1 fill:#e8f5e9
    style EVAL fill:#fff3e0
    style S5 fill:#ffebee
    style S6 fill:#e3f2fd
```

## 图例

| 颜色 | 含义 |
|------|------|
| 🟢 绿 | 领域分析（本 Skill 的创新点） |
| 🟠 橙 | 两阶段评估（成本控制核心） |
| 🔴 红 | 自检反思（PAPER 认为最易翻车） |
| 🔵 蓝 | 交付（最终产出） |

## 关键回路

- **阶段一内部**：途径 3 实地检查的结果可以回补途径 1/2 的候选发现
- **阶段二内部**：自检发现缺口 → 回到补搜（共享 ≤2 轮预算）
- **跨阶段**：补搜时缺口在白名单内无法填补 → 启用阶段一留下的储备清单补位
- **跨会话**：领域档案落盘后，下次同领域查询直接复用，跳过阶段一
