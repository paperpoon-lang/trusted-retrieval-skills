# 可信检索搭建 Skill（元层次）— 设计总结

> 撰写日期：2026-07-24（2026-08-13 同步至 v2.5.1）
> 对应 Skill 版本：v2.5.1（main @ d7a2667；v2.5 走查 #6–#9 落地 + v2.5.1 走查 #11 与口径族收编）
> 文档定位：向企业导师/同事说明「为什么这样设计」的完整思路

---

## 一、一句话概述

一个让 Agent **在陌生数据领域现场搭建可靠检索方案**的元层次 Skill——不预装任何信源知识，而是教 Agent「如何发现信源、如何评估可靠性、如何构建白名单」。是人口/销售两个预置 Skill 背后那套六模块方法论的自我复制版本。

---

## 二、设计理念

### 理念 1：元层次——从「做菜」到「写做菜的菜谱」

人口数据 Skill 和销售数据 Skill 是两道菜。六模块是工序。元层次 Skill 是把工序本身写成菜谱——给 Agent 的不是「怎么查人口」，而是「怎么为一个新领域设计检索方案」。

正式定义：元层次（meta-level）= 关于 X 本身的 X。它不直接解决用户问题，而是让 Agent 获得「为新问题搭建解决方案」的能力。设计野心：**不是多做一个 Skill，是让这个 Skill 系列从此可以自我复制。**

### 理念 2：白名单是产出物，不是输入物

人口/销售 Skill 的信源白名单是预装的（写死在 SKILL.md 里）。元层次 Skill 没有预装的白名单——白名单是 Agent 现场构建的产出物。

这个设计破除了一个伪问题：既然没有白名单，Agent 要不要「破例」搜非白名单网站？答案是——没有白名单就没有「破例」。阶段一的任务就是构建白名单，构建完成之前不存在禁区。

### 理念 3：先定义失败（继承自人口数据）

```
失败模式                           →  反向推出的设计决策
─────────────────────────────────────────────────────────
错把领域 A 的信源结构套到领域 B     →  强制领域分析先行（先问「有没有唯一权威」）
不知道去哪找可靠信源                →  三途径发现（记忆 + 搜引用 + 实地检查）
SEO 内容农场污染搜索结果            →  搜引用不搜推荐 + 英文辅助搜索
候选太多、评估成本爆炸              →  两阶段过滤 + 达标即停
信源评估标准不统一                  →  可执行的检查项：身份/溯源/方法论/时效/机构
归因当数据                          →  数据/归因信源分离
补搜无限循环                        →  总预算 ≤2 轮 + 补位必先深评
「不适用」被评估前预设，绕过深评        →  「不适用」从时机约束改为证据约束（须附深评记录）【N=3 实测】
降级信源没有名分（通过/不可用之外的第三态） →  3.3 三态定义：降级=带保留通过，可填槽但数据带 ⚠️【评议 A】
聚合标签冒充终态，跨轮比对失真         →  槽位终态必须填具体机构名，聚合标签按沉默跳过处理【N=3 实测】
模糊直觉伪装成精确数字，污染审计记录    →  被引信号定性化（强/中/弱），拒绝数值阈值【评议 A】
单一主体口径冒充全国汇总（有机构名、有出处，口径层级被悄悄降级） →  3.1 新增口径层级行：声称层级须与出处主体层级匹配，冒充淘汰、诚实标注豁免【8/5 实测②】
死磕公开不可得的目标粒度，补搜耗尽才暴露边界                →  双判断（停止是证据决定：核对表 / 未试动作枚举 / 阻断事实+URL）+ 粒度缺口交付规格 + 粒度信号沉淀进覆盖范围字段（可得性预检砍除）【8/5 两次实测】
交付侧口径滑动：复用更新时异口径数字静默替换边界值、混入序列制造「一致」假象 →  关键口径三要素（层级×范畴×边界）+ 档案更新口径连续性检查 + 异口径数字禁止进入不等式推断【v2.5 复跑 9-R，走查 #11】
等价判断失守：范畴级差异被误判为措辞级（识别了、标注了、照用了） →  口径等价判定（逐维文本比对、默认拒绝、等价须举证）+「显式≠可用」+ 量级衔接陷阱条【v2.5.1 场景 12 实测】
```

### 理念 4：约束大于判断（继承）

不给 Agent 需要主观判断的指令，给可机械执行的硬规则。最典型的例子：信源评估拆成五个可执行的检查动作（身份/溯源/方法论/时效/机构），每个都有明确的通过/不通过标准，而非「判断这个网站可不可靠」。

### 理念 5：搜引用不搜推荐（元层次独有）

人口/销售 Skill 用预装白名单绕过了 SEO 问题。元层次没有白名单，必须在开放网页中发现信源。解决方案：不搜「什么是可靠信源」（SEO 重灾区），搜「谁在使用什么信源」——看这个领域的从业者、研究者在引用什么，不看谁在说自己好。配合英文搜索绕过中文内容农场。

## 三、架构

### 七步流程（六模块 + 领域分析前置）

```
第零步：检查现有 Skill（已有预置 → 转交，无 → 继续）
     ↓
阶段一：领域分析
  第一步：判断信源结构（树状 / 网状 / 单源垄断）
  第二步：发现候选信源（记忆 + 搜引用）+ 第二步附：实地验证（仅可访问性，禁评估）
  （第零步后另有环境检查：域名搜索 / 抓取 / 工作区可写，失败显式降级）
  第三步：两阶段评估（低成本过滤 → 排序 → 达标即停）
  第四步：构建白名单
  第五步：显式记录（含槽位终态、储备清单）
  第六步：落盘（领域档案）
     ↓
阶段二：执行标准检索
  搜索规划 → 信源约束 → 接地规则 → 补搜 → 自检 → 可审计交付
```

### 跟前两个 Skill 的架构差异

| 模块 | 人口/销售 Skill | 元层次 Skill |
|------|----------------|-------------|
| 领域分析 | 不需要（领域已知） | **新增前置于六模块之前**——白名单的生成器 |
| 信源约束 | 预装白名单 | 动态构建的白名单 |
| 补搜机制 | 领域特定触发器 | 通用触发 + 储备清单补位（补位必先深评） |

领域分析模块是这个 Skill 的真正创新点——它把「数据工程师为一个新领域设计检索方案」这个人工工序自动化了。

### 封槽机制：达标即停（下限封槽）

核心设计：第二遍深评不是评完所有候选，而是按排序逐个评，每个槽位达到下限即封槽。

| 结构 | 槽位 | 封槽条件 |
|------|------|---------|
| 树状 | 每优先级层级 | 该层 ≥1 即封 |
| 网状 | 数据信源 | ≥2 独立平台即封 |
| 网状 | 归因·法定披露 | ≥1 即封 |
| 网状 | 归因·第三方鉴证 | ≥1 即封（两类：财务审计 / 方法论认证，记录须注明类型） |
| 网状 | 归因·第三方观点 | ≥2 即封 |
| 单源垄断 | 唯一信源 | ≥1 即封 |

每个槽位终态只能是三者之一：已填 / 空槽标注 / 不适用。**沉默跳过即违规。** 这个规则是场景 2 实测翻车后补入的——网状归因三槽位原本嵌套在一行里，subagent 跳过两个，翻车后拆成独立行。终态与白名单必须填具体机构名，聚合标签视为未填。「不适用」终态须附深评记录（v2.4，N=3 实测驱动）。

## 四、关键设计决策

### 决策 1：为什么领域分析放在六模块前面，而不是在信源约束里做？

因为信源约束模块原本假设白名单是已知的。元层次的白名单是未知的——需要在碰任何数据之前先搞清楚「这个领域长什么样」。领域分析不是信源约束的子步骤，而是它的前置生成器。

### 决策 2：为什么选「达标即停」而不是「评估所有候选」？

成本控制。最坏情况：15 个候选，每个深评需要 3 个页面打开 = 45 次工具调用——还没开始搜数据。达标即停把成本从「候选数 × 深评成本」压到「槽位数 × 深评成本」，与领域复杂度脱钩。

代价是白名单质量被排序信号锁死——如果第一遍的弱信号把真正的权威信源排到了后面，早退会用次优信源填槽。实测中这个风险由独立性判定兜底（两个独立信源的平均能压住个别次优）。

### 决策 3：为什么归因信源拆三个子槽位？

销售数据 Skill 的经验——归因来源本身有可信度差异：公司年报（法定披露，有监管约束）≠ IOSCO 审计（第三方专业鉴证）≠ 券商研报（独立观点，需 ≥2 家交叉）。不能归为一类。元层次把这个分层结构化了。

### 决策 4：为什么加「储备清单」？

达标即停必然遗留未评候选。与其丢弃或用「不合适」模糊标注，不如保留为储备——阶段二补搜时优先从储备补位（补做深评后才可用），而非重新发现信源。未评候选从「现在必须评的负债」变成「将来按需取用的资产」。

### 决策 5：为什么强调「英文辅助搜索」？

中文搜索结果中内容农场、SEO 优化文章占比高。英文搜索结果的学术/机构占比通常更高。这不是理论判断——是人口/销售 Skill 开发过程中的实操经验：用中文搜「人口数据」第一页多是百度百科和自媒体，用英文搜「population data」第一页是 World Bank 和 UN。

### 决策 6：为什么被引信号用定性（强/中/弱）而不是数值阈值？

模型从搜索结果估计的被引频次是模糊直觉。写成数字阈值（如「被引 ≥3」）会把不可验证的直觉伪装成精确标准，审计记录的精度就超过了事实的精度。定性化不是让判断变稳定，而是停止假装它比实际更准。（评议 A 与 B 在此冲突，采纳 A；B 的量化阈值方案拒收，理由是「判据写行为，不写数字」的方法论一致性。）

### 决策 7：为什么「不适用」从时机约束改为证据约束？

原规则「必须在第一步声明」为防偷懒改口，N=3 实测证明它矫枉过正：轮 1 在评估前声明审计槽「不适用」，轮 2/3 均找到可填实体——防住了懒，制造了急。改为：终态只在深评无果后生效，且必须附深评记录；第一步可写「预期不适用（待验证）」，无终态效力。防偷懒由证据继承，不由时机继承。

### 决策 8：为什么阶段二保持最小集（与兄弟 Skill 的同步债）？

元 Skill 阶段二服务任意领域，机制必须通用；领域特化机制（5 触发器、审计分层、三档标注）属于预装知识，与元层次「不预装领域知识」的定位冲突。二者关系声明为「有意最小集」而非同步债，待元 Skill 产出第三个预置 Skill 时重议。（评议 A 问题 2 的正式回答。）

## 六、优越性

### 1. 自我复制——从两个 Skill 到一个 Skill 系列

元层次 Skill 将六模块方法论从人工操作升级为 Agent 可执行的元能力。它的自然产出物（领域档案）经过人工审核即可升级为新预置 Skill——人口/销售就是这么诞生的，下一个不再需要从头设计。

### 2. 领域无关——一套方法论覆盖三种结构

树状（有唯一权威）、网状（多源无权威）、单源垄断——三种信源结构的发现和评估策略全部内建。实测六个场景覆盖全部三种结构。

### 3. 成本可控——达标即停

深评成本不随候选丰度增长。六场景实测中，阶段一与阶段二的工具调用比稳定在 4:6 左右，未出现「建白名单比搜数据还久」的情况。

### 4. 可审计——每个决策可追溯

领域分析记录包含完整的探索过程、淘汰原因、槽位终态、排序依据、储备清单。不仅是「搜到了什么」，还包含「为什么信这个」、「淘汰了什么」、「还有什么备用」。实测翻车（场景 2 归因子槽位缺失）正是因为可审计性——沉默跳过能被发现。

### 5. 实战验证——不是纸面设计

六场景实测 + 翻车修复复测闭环（v2.1→v2.2）+ 两篇外部同行评议（8.2/10、A-）驱动的六处补丁（v2.3）+ N=3 跨轮一致性复跑与三处实测修复（v2.4）+ 百川探针 Q1 定论。核心实测结论：数据层稳定、归因层漂移——白名单成员跨轮漂移，但交付答案不漂移，架构把方差收容在危害最小的归因侧。已知未测项在测试实录中显式列出，不掩盖。

## 八、已知局限（诚实标注）

1. **排序信号质量未被系统验证**：达标即停的质量依赖于第一遍信号能正确排序。实测中排序偏保守但不致命（储备清单质量好、独立性判定兜底）。权威信源低调、内容农场张扬的极端场景尚未触发。
2. **深评结论可复现性**：已有初步答案——百川探针（强制深评 ×2）定论：当前判定层稳定（两轮零翻转），历史翻转以检索层为主（网站改版致证据消失）+ 标准演进（v2.1→v2.3 方法论检查项收紧），跨版本比较含伪影成分。N=3 显示分歧以检索层为主，但结论限于小样本初步画像。
3. **非中英双语领域未测**：日语、葡语等非中英信源的关键词翻车风险未覆盖。
4. **领域档案跨会话复用**：场景 7 已实测（13/13 判据，v2.4.2 补丁闭环）；v2.5 复跑中 8-R/9-R 意外触发保鲜期复用路径，行为正确（意外实测再验证）。残余未测：v2.5.1 新增的「旧档字段顺手回填」与「口径连续性检查」实战表现——9-R 是复跑触发，非常态复用。
5. **单源垄断的豁免边界**：什么算「真·单源」、什么算「找不到第二源」，边界由 Agent 判断，存在误判风险。
6. **单 FM 评估**：全部测试在单一基座模型/harness 上执行，跨 FM 可移植性未知（跨 FM 复跑列入远期）。
7. **非文本数据源未覆盖**：API / Excel / 付费墙（Wind/Bloomberg）信源的评估适配规则缓建。
8. **双判断的自评漂移残余**：方案 B 的缺口闭合 / 期望收益判断本质是 FM 自评软约束。现有对冲：证据要求（核对表 / 枚举 / 阻断事实+URL）+ 停止无记录即违规 + 硬上限兜底 + 场景 10 对照组实测（防躺平方向）。小样本下「差不多得了」漂移不能排除，靠协议核销断言（V.口径 / V.2）在后续实测中持续压制。
9. **口径规则族实测覆盖**：口径族规则经六场景复跑 + 12-R 两场景针对性实测（12-Ra 从零同诱饵 / 12-Rb 夹具复用，v2.5.2 修复后全判据通过）。**剧透态**——SKILL 文本实例剧透，效度限于机制形态；独立边界发现仅 11/11B 两个无剧透场景。
10. **SKILL 文本实例的剧透效应**：正文实例（ACEA/JATO、有机茶园）助执行但剧透回归测试——复跑效度降级为「机制形态」验证。示例保留 / 改写 / 删除的取舍待专议（教学价值 vs 测试效度的真实张力）。
11. **场景 14 未排期**：无剧透 + 微妙异口径诱饵（同单位、量级连续、新领域）验证——12-R 仍为剧透态，真正的无剧透微妙案例验证留给场景 14（已知开口，不遗忘）。
